# V2教材 検証チェックリスト（指導員用）

> **これは生徒用のテキストではありません。** v2教材を公開前に点検するための確認表です。
> 対象は `v2/` の21レッスン。応用・発展はテキストを作っていないので対象外です。

## 使い方

1. **A（全体チェック）を1回**やる → 2. **B（レッスンごと）を01から順に**やる
3. 結果を **F（記録表）** に書く → 4. ×・△は `v2/開発日誌.md` に日付・実施者つきで追記する

| | |
|---|---|
| つける記号 | **○** 問題なし ／ **△** 気になる点あり（内容を書く） ／ **×** できない・動かない |
| 直してよいもの | 誤字、表現の言い回し、画像の差し替え |
| **直さずに報告するもの** | **ピン番号・サンプルコード・IRコードの値・レッスンの順番**。全レッスンに影響するため、その場で直さない |
| 報告先 | `v2/開発日誌.md`（レッスン18のWiFiは `検証_WiFiライブラリ.md` の記録らんへ） |

### いちばん大事な進め方

**自分の知識で補わないこと。** テキストに書いてあることだけを見て、書いてある順番どおりに手を動かしてください。
「ここは言わなくても分かるだろう」で飛ばしてしまうと、生徒がつまずく場所が見つかりません。

### 用意するもの（検証する側）

- [ ] 生徒が使うのと同じPC（Arduino IDE入り。Chromebookは対象外）
- [ ] ロボットカーキット（Osoyoo V2.1）一式 … 実践10以降で必要
- [ ] **2台目のロボット** … 実践20・21の対戦で必要
- [ ] タブレット（iOS／Android）… 実践18・19・20で必要
- [ ] ブレッドボード、ジャンパー線、LED、抵抗330Ω、その他の貸出部品
- [ ] コース（チキンラン用の線、迷路、ライントラッキングの黒線）… 実践12・13・14・16・17で必要

## A. 全体チェック（最初に1回だけ）

### A-1 表示とリンク

- [ ] 21本すべてが、**生徒に配る形**（GitHub／印刷／Googleサイトなど実際の配り方）で崩れず読める
- [ ] 画像がすべて表示される
- [ ] **ファイル名にスペースが入っている画像**が表示される（ビューアによって崩れることがある）
      → 07の `IRsensor_variable resistor.png`、10の `image/parts/` の9枚、20の `Apple APP Download.jpg`
- [ ] 本文中のリンク（`common/motor_driver.h`、WiFiEspのzip、他レッスンへの参照）を**全部クリックして**飛べる

### A-2 生徒が読む言葉

- [ ] 小学生に難しい言葉が、説明なしで出てこない
- [ ] 1つの手順で1つの動作になっている（1手順に2つ以上の作業が入っていない）
- [ ] 「先生に言って借りてくる」と書いてあるものが、**教室に在庫としてある**
- [ ] 部品の呼び名が、教室で実際に使っている呼び名と合っている

### A-3 教育の型（設計書 §6・§7）

以下は機械的に確認済みですが、**中身が埋まっているか**は目で見てください。

- [ ] 8つの節がそろっている（ミッション／身につける力／今回使う技術／ミッションの準備／メインミッション／確認／やってみよう／まとめ）※21本すべてに存在することは確認済み
- [ ] 「やってみよう」に**具体的な課題**が1つ以上ある（「工夫してみよう」で終わっていない）
- [ ] 「まとめ」が**4項目**（やったこと／わかったこと／感じたこと／つぎやること）＋**画像1枚**の指示になっている
- [ ] 「ファイルを保存してクラウドに上げよう」がある（21本すべてに存在することは確認済み）
- [ ] 「できるようになったことをチェックしよう」の項目が、冒頭の「このレッスンで身につける力」と**同じ内容**になっている

### A-4 コードとテキストの一致

- [ ] 本文に載っているコードと `sample/` の `.ino` に**食い違いがない**
      （本文は抜粋のこともあるので、**ピン番号・関数名・`#define`の値**が合っているかを見る）
- [ ] ロボットレッスン（11〜21）の各スケッチフォルダに `motor_driver.h` が入っている（※入っていることは確認済み）
- [ ] `sample/` のフォルダ名が**旧レッスン番号のまま**のものがある。生徒の混乱にならないか判断する
      → 03は`lesson_02_*`、05は`lesson_08_*`、06は`lesson9_0*`、07は`lesson_11_*`、08は`Lesson_15_*`、09は`Lesson_16_*`
      （11以降は新番号。入門は本文にコードを貼る形なのでフォルダ名が本文に出てこない）

### A-5 90分に収まるか

- [ ] 各レッスンが**90分**で終わる分量になっている（かかった時間をFの記録表に書く）
- [ ] 終わらなかった場合、どこで区切れるかを書く

## B. レッスンごとのチェック

### 毎レッスン共通の手順

1. テキストの先頭から、**書いてあるとおりに**進める
2. コンパイルが通る／書き込める
3. テキストの「**確認**」にあるチェック項目を、**実際に全部やって**○×をつける
4. テキストの「**やってみよう**」を1つ以上やってみて、その指示だけでできるか見る
5. つまずいた場所・分からなかった言葉・かかった時間を記録する

### レッスンごとに特に見るところ

**★** は設計書で「実機での確認が必要」とされている未検証の項目です。**必ず見てください。**

## C. 技術の重点確認（設計書で未検証の項目）

Bと重なりますが、**ここだけは結果を数字・事実で書いてください。** 全レッスンに影響します。

### C-1 ENA（右モーターPWM）のピン

| レッスン | 設計上のピン | 実機で動いたか |
|---|:--:|---|
|11・12・13・15・16・18・19|D3| ○ / × （ |
|17|D3（サーボがD9・D10を使うため必須）| ○ / × （ |
|14・20・21|D9（`#define USE_IR_ROBOT`。IRremoteがD3のPWMを潰すため）| ○ / × （ |

- [ ] 14・20・21で、**D3のままだと動かない**ことも確かめた（理由の説明が正しいかの裏取り）
- [ ] 14・20・21の本文に「つなぎかえる理由」と「終わったらD3に戻す」が書かれている

### C-2 モーターの左右

`motor_driver.h` は **12・11＝右 / 7・8＝左** で統一してあります。

- [ ] 実機の配線で、この定義どおりに**右が右・左が左**に動いた
- [ ] 違っていた場合、**配線が逆なのか・コメントが誤りなのか**を書いた（→ 設計書§8③）

### C-3 赤外線（IRremote v4化）

- [ ] リモコンのボタンで `command` が2けた（`0x18` など）で出た。実際に出た値を書く
- [ ] 20・21の弾（NEC `0xAA`／`0xBB`）で撃てた・当たったら倒れた
- [ ] 生徒PCに入るIRremoteは**1バージョンだけ**。旧カリキュラム（`Lesson_00`〜）と混ぜられないことを周知した

### C-4 その他

- [ ] ブザーの極性が個体で逆になっていないか（逆のものがあったら台数と対処を書く）
- [ ] 20・21の旋回が「その場で回る」動きになっていて、13で測った90度の時間がそのまま使えた
- [ ] 19の操舵（`==` 修正後）のハンドルの効き方が、テキストの説明と合っている
- [ ] レッスン18のWiFi → `検証_WiFiライブラリ.md` の確認A（zipインストール＋本編スケッチでの操縦）を実施した

おきたこと：▲を押すと前に進むが、◀を押すと右に回る
シリアルモニタ：0x18 と表示されていた
試したこと：7・8の線を入れかえたら◀で左に回るようになった
