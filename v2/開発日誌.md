## 2026-09-23

### 議題：現行21レッスンを4段階構造へ再編し、v2として全レッスンを執筆

#### 経緯

『ロボ部カリキュラム 編集方針』（Claudeへの作業指示書）に基づき、既存教材の再構成に着手した。

当初は「現行レッスンを土台に、固定順序の30レッスン構成へ再編する」案を作成したが、方針書 §11「編集時に避けること」に

- 月別・学期別の固定進行にする
- 「○回受講したら進級」とする
- 全員が同じ速度で進む前提にする

とあり、この案は前提から外れていたため破棄した。方針書 §2 が求める**入門／実践／応用／発展の4段階構造**へ作り直した。

あわせて `アイアルク_経験項目_新カリキュラム設計.xlsx` を確認。96の経験項目が6カテゴリに整理され、「ロボ部 入門／実践／応用／発展」の列が空欄になっていることから、これが設計の入力欄だと判断し、各段階の記述を経験項目番号に対応づけた。

#### 決定事項

**段階の定義**

| 段階 | 使うもの | 教材テキスト |
|---|---|---|
| **入門** | Arduino＋ブレッドボード（ロボットカーを使わない） | あり・9本 |
| **実践** | ロボットカー（組み立て〜Bluetooth対戦＝キット完成） | あり・12本 |
| **応用** | 自作ロボット（オリジナルロボット作成） | 現段階では作らない |
| **発展** | 自作ロボットの改造（新しいロボット対戦） | 現段階では作らない |

分類基準は**ロボットカーを使うかどうか**。入門は部品を単体で知り、実践でロボットに載せる。

応用・発展のテキストを作らないのは着手順序の問題であり、将来的に作らないという意味ではない。運用の記録がたまってから書くほうが実態に合う。作る場合も手順書の形にはせず、考えるための問いかけ・チェックリストの形にする（方針書 §12）。

#### レッスンテキストの構成

方針書 §5 に沿って全21本を統一した。

```
ミッション → 身につける力 → 今回使う技術 → ミッションの準備
→ メインミッション → 確認 → やってみよう → まとめ
```

セクション名は「制作・挑戦→メインミッション」「テスト→確認」「改良→やってみよう」「振り返り→まとめ」とした。

**まとめの運用**

- 書く場所：Googleサイトの生徒ごとのまとめページ
- 頻度：**1日1回**（複数レッスンを進めた日も、1レッスンが終わらなかった日も1回）
- 必ず書く4項目：やったこと／わかったこと／感じたこと／つぎやること
- **スクリーンショットか画像を必ず1枚**

頻度がレッスン単位でなく1日単位のため、**そのレッスンのチェックリストは各レッスンのテキスト側に置き**、生徒はそれを見ながらまとめページを書く。「全部でなくてよい」という逃げ道は置かない。

#### 実地調査で判明した問題

現行20ファイル・5,771行を全て読んで点検した。

| 問題 | 内容 | v2での対応 |
|---|---|---|
| **振り返りがない** | 「まとめ」は教えた知識の要約（L06は `go_Advance()` の説明、L22は `switch` の書式）。最も近いL15の「出来たことをチェックしよう」も技能の自己チェック止まり | 全21本を新形式に差し替え |
| **モーター変数名が3系統** | `speedPinR`系（L04-05,06,10,12,17）／`m1`〜`e2`系（L14）／`speedPinRight`系（L20,21） | `motor_driver.h` に集約 |
| **右PWMがL17だけD3** | 他はD9。L17はサーボがD9を使うため | **最初からD3に固定**、D9をサーボ用に空ける |
| **L14の左右コメントが逆** | `#define m1 7 //右モーター` だが他は7・8＝左 | `motor_driver.h` で 12・11＝右／7・8＝左に統一 |
| **まとめ節がない** | L04-05、L18、L21 の3本 | 新形式で追加 |
| **ミッションの準備がない** | L10（部品リストなし） | 追加 |
| **見出しの重複** | L12とL14が両方「障害物センサーを使って物体追従を行う」 | 修正 |
| **部品リストのコピペ誤り** | L12・L14にL09由来の赤外線コントローラーが混入 | 修正 |
| **レッスン総数の誤り** | 従来「22本」と記載されていたが、実数は**21本**（20ファイル・L04-05が2回分） | 訂正 |

**文法解説の空白**も判明した。`for`/`while` はL04-05・L17・L21のサンプルに解説なしで登場し、`switch` はL16で無解説に出てL22でようやく解説、自作関数の解説もL22のみだった。独立レッスンを作らず、既存レッスンの中で扱うことにした（方針書 §11）。

| 文法 | 扱う場所 |
|---|---|
| `for` / `while` | 04「やってみよう」（2つのLEDを交互に光らせる） |
| `switch` | 09（サーボ）で解説を追加 |
| 自作関数 | 11（`motor_driver.h` 導入時）と 21（必殺技） |

#### 修正の必要性「大」3本の扱い

| 旧 | 問題 | 対応 |
|---|---|---|
| L04-05 | 1ファイルに2レッスン分。90分で終わらない。まとめ節なし | **10（機構の組み立て）と 11（配線とプログラム）に分割** |
| L18 | 接続でつまずくと走行に到達しない | **接続確認だけを独立工程に**（IPアドレスが出るまで次へ進まない） |
| L21 | サンプルコードが4種あり、どれを使うか不明瞭 | `lesson_21_sampleA/B` を正とした |

L19（Bluetooth）も、旧L19削除の影響でいきなりロボット＋タブレットになっていたため、**「受信:」が出るまで走行に進まない**確認工程を追加した。

#### 「確認」を実質的な工程にした

現行教材では動作確認が曖昧だったため、次を各レッスンに置いた。

- **電源を入れる前の配線チェック**（04・11）— まちがった配線で電源を入れると部品がこわれるため
- **通信できたかの確認**（18・19）— つながっていないのに走らせても動かない
- **センサー値の確認**（15・16）— 走らせる前にシリアルモニターで値を見る
- **症状別トラブルシュート表**（全レッスン）

#### ブザーをデバッグの道具として一貫させた

入門06で鳴らし方のパターンを作り、以降は「いまどの処理に入っているか」を音で知らせる用途に統一した。`motor_driver.h` に `beep(回数, 長さ)` を用意。

レッスン11で「音は鳴るのに走らないなら、原因はプログラムの外（配線や電池）」という切り分けを教え、13では区間ごと、15では判断ごと、17では判断内容を音で知らせる設計にした。

#### 入門と実践の接続

段階を分けたことで、入門で得たものを実践で使う導線が必要になった。

| 入門で作るもの | 実践で使う場所 |
|---|---|
| 05 IRコード記録表 | 14（リモコン操縦）、20（対戦） |
| 11 速さと距離の表 | 12（チキンラン） |
| 13 90度曲がる時間 | 14、21 |
| 09 サーボの首ふり | 17（周囲スキャン） |
| 09 `switch` 文 | 14、21 |

トラッキングセンサー・Bluetooth・WiFiは**入門に単体レッスンを置かない**（旧L13・旧L19は復活させない）。実践で直接ロボットに載せて扱う。

#### 応用・発展で「正解」を渡さない設計

レッスン17と21は、応用段階への橋渡しとして設計を変えた。

- **17**：サンプルコードを「正解」ではなく「たたき台」と明記。迷路の解き方（一番広いほうへ／右手法／止まらず走る）を提示し、**選ばせて理由を説明させる**
- **21**：必殺技を「①困っている場面 → ②解決方法 → ③動きの順番 → ④かかる時間」の順に設計させ、**使って直してまた使う**ところまでを到達課題にした
